# Asset Mapping Register

`asset-mapping-register.tsv` is a versioned reference record of confirmed model-to-texture slots and table-declared relationships. Published packages include it under `docs/`. The runtime resolver does not load this register; unverified rows do not change export behavior.

## Status

- `exported-slot`: the focused OBJ export's texture-slot report marked this model, mesh, and slot as exported.
- `exported-slot-unverified`: the export wrote a texture, but conflicting physical copies or multiple side-specific fields leave the intended binding unconfirmed. The written texture must not be treated as a confirmed game mapping.
- `table-declared-slot-unverified`: a typed CFT row declares the model and texture fields, but the model slot has not been verified by export.
- `model-resource-missing`: the table declares the model, but the current resource scan did not find its file. Any listed texture and motion paths remain table declarations.
- `model-reference-incomplete`: the source field names a directory without a complete model filename. The record retains the original field and any same-side texture declaration; no model slot is established.
- `slot-unresolved`: the model and slot were decoded, but the focused export did not establish a texture binding, including cases where the logical path is known but its physical copies conflict.

Rows describe individual slots. A successful row can coexist with other unresolved meshes in the same OBJ export.

## Fields

- `model_path` and `texture_path` use paths relative to the game resource root.
- `global_texture_slot` is the LTB skin slot; it is blank until slot evidence exists.
- `mapping_source_or_field` names the resolver source for exported slots or the CFT field for declared relationships.
- `skeleton_or_bone_names` records a node count and hierarchy hash when inspected; the linked node table retains every name and parent. Counts include the scene root.
- `bone_or_socket_binding` records embedded model sockets or the raw CFT attachment target type. An embedded socket does not establish which accessory uses it. Blank values mean unknown, not absent.
- `motion_model_path` records a motion-model path declared in the same typed CFT row. It does not claim that OBJ export contains the animation.
- OBJ currently exports geometry and textures. It does not preserve skeleton bones or animation tracks.

Starting with v1.2.7, opening a CFT displays all decoded rows in a table with row numbers, original field names, a frozen `RecordId` column and numeric sorting. Export XLSX from the preview window, the file context menu or with `--export-cft-xlsx --input <file.cft> --output <file.xlsx>`. Its first column is the serialized `RecordId`; it is distinct from the zero-based row selector used in this register. Export preserves source order regardless of preview sorting. The [preview checks](evidence/cft-grid-20261105-validation.tsv) cover both CharacterType and CharacterItem, including every cell and duplicate-column guards.

## Snapshot

The register contains 937 records: 915 confirmed exported slots, seven unresolved slots, eight declarations without a matching decoded model slot, four missing model declarations and three incomplete model references. No current row is marked as a written but unverified slot. These are recorded samples, not a full-game coverage count. Repeated physical model copies are retained in the evidence tables and deduplicated in the register.

### Embedded model and animation associations

The [combined structure inventory](evidence/ltb-associations-20261105-models.tsv) covers 373 distinct physical LTB files from the three earlier snapshots. Their 380 physical witnesses include seven repeated files: three FireAim hair models shared with the base snapshot and four files shared by the CharacterItem base and side snapshots. The [resource table](evidence/ltb-associations-20261105-resources.tsv) retains each archive path, logical path, stored size, index MD5 and actual SHA-256. These records extend the existing sample coverage; they do not represent all game models.

The [376 child-model entries](evidence/ltb-associations-20261105-child-models.tsv) contain 373 implicit self entries and three serialized external references. Child index 0 is the containing model and has no serialized path. FireAim BL, GR and SP body files each declare child index 1 as `M-motion_blue.ltb`. This provides a second source for the body/motion relationship, alongside the CFT field. Each external child has zero serialized animation bindings. The three arm files contain only their self entry. Neither a child declaration nor an absent binding override chooses among the four physical motion copies or verifies playback.

The [8,867 animation bindings](evidence/ltb-associations-20261105-animation-bindings.tsv) retain the child index, binding order, animation name and serialized dimensions/translation. Every recorded binding belongs to child 0 and uniquely matches an embedded animation name at the same index, ignoring case. The dimensions and translation are binding metadata; they are not per-bone keyframes. The [17 weight sets](evidence/ltb-associations-20261105-weight-sets.tsv) preserve names and per-node float32 values: `Upper`/`Lower` on the body and motion files, and `BaseTracker` on the arms. These are node weights for animation blending, not vertex skin weights.

An [independent binary read](evidence/ltb-associations-20261105-validation.tsv), using standard LZMA decompression, reproduced every new field from the stored resources. All earlier model-summary fields, nodes, animations and sockets remain unchanged across the 380 witnesses. [Forty synthetic checks](evidence/ltb-associations-20261105-guards.tsv) cover implicit self entries, quoted child paths, zero child bindings, exact float bytes, duplicate/reordered/missing animation names, invalid counts, non-finite values and truncation. Rejected files emit no detailed association rows. The current source [structure tool](https://github.com/LRolinx/CFRezManager/tree/main/tools/LtbStructureAudit) produces these tables; OBJ export still contains geometry and textures.

### Texture copy consistency

v1.2.9 compares every decoded copy of a logical texture path. Matching index MD5 values or a valid MD5 on each individual file do not establish pixel equivalence. Every copy must decode with matching dimensions and BGRA pixels, including alpha. The [six recorded physical DTX copies](evidence/texture-copy-20261105-variants.tsv) cover three conflicting paths: CFPL GR headset and The_Fates_Casual GR hair/hat. All six actual MD5 values match their index entries, but each logical path has two different pixel hashes. A [fresh scan of all 482 archives](evidence/texture-copy-20261105-scan.tsv) reproduced their stored hashes. The active game copy remains unverified; directory numbering is not used to choose one.

The [four prior unverified outputs](evidence/texture-copy-20261105-conflict-status.tsv) now retain their original CFT references without writing a PNG. Their per-slot export report says `export-failed`, which means the PNG was not written; both source copies can individually decode. The register marks these slots unresolved until a physical version can be established. The hair base was already unresolved for the same conflict. All [915 confirmed records](evidence/texture-copy-20261105-confirmed-regression.tsv), covering 939 physical mesh-slot witnesses, retain identical PNG bytes to v1.2.8.

The GUI and command-line OBJ exporters use the same lookup policy: a matching resource that is undecodable or conflicting does not fall through to another extension or a nearby local copy. A path absent from the global index can still use local lookup. Explicit physical paths remain individually readable. Standard bitmap decoding also precedes raw-TGA recovery, preventing valid PNG metadata from changing the interpreted image dimensions.

The [61 checks](evidence/texture-copy-20261105-guards.tsv) include changed first/last-row RGB and alpha, dimensions, invalid copies, reversed order, MD5 metadata, explicit physical references, recognized but invalid PNG data and PNG metadata whose encoded size resembles raw TGA. The [reusable check tool](https://github.com/LRolinx/CFRezManager/tree/main/tools/TextureCopyCheck) runs 49 synthetic cases without game files; these cases also run in the release workflow. Twelve additional checks use the recorded DTX snapshot.

### CharacterItem side bindings

The side follow-up preserves every model-reference column, including `_GRFSocketItemModelFile` and `_BLFSocketItemModelFile`. Shared paths retain both GR and BL texture fields; the declared columns determine the side even when a filename has a different suffix. The [183 selected model rows](evidence/characteritem-side-20261105-cft-links.tsv) cover 138 CFT records. There are 181 existing model rows, one missing model and one directory-only reference in this selection. The [raw fields](evidence/characteritem-side-20261105-raw-fields.tsv) also retain the two directory-only rows removed from typed model/texture pairing, for 140 recorded CFT rows in total.

All 482 REZ archives were scanned without errors. The [307 requested paths](evidence/characteritem-side-20261105-targets.tsv) produced [308 physical resources](evidence/characteritem-side-20261105-resources.tsv); their bytes were checked after rebuilding nine filtered archives. A [fresh scan](evidence/characteritem-side-20261105-scan.tsv) reproduced every stored hash. The exact `DX_NGold_WAIST_BR.ltb` declaration was absent. Its `_BLFSocketItemModelFile` column establishes a BL declaration, while its `BR` filename does not establish an alternative skin.

Fourteen [export jobs](evidence/characteritem-side-20261105-jobs.tsv) verified both sides of all 181 existing model rows: 390 physical mesh-slot rows, deduplicated into 382 new register entries. Every exported path equals the same-side CFT field and uses a decoded native slot. Against v1.2.6 behavior, 388 formerly unresolved rows now export, one BL hair export changes from the GR skin to its declared BL skin, and one existing GR export keeps identical PNG bytes. These changes are included in v1.2.8; v1.2.7 added the CFT table viewer.

The [slot evidence](evidence/characteritem-side-20261105-export-slots.tsv) retains source DTX pixel hashes, output pixel hashes and PNG hashes. Of 390 rows, 388 match the original BGRA pixels exactly. The male and female CamelBag GR exports retain every RGB byte but remove an entirely zero alpha plane for diffuse material visibility; replacing only output alpha with zero exactly reproduces the recorded original pixel hash. All [216 physical DTX files](evidence/characteritem-side-20261105-texture-copies.tsv) decoded successfully.

Use `row:CharacterItem.CFT#2372:GR` or `row:CharacterItem.CFT#2372:BL` for the MasterHERO hair skins. Identity and positive `recordid:` selectors also accept the side suffix. Row indices and serialized record identifiers are separate domains: this hair row has `RecordId=2374`, and pouch row 2373 has `RecordId=2375`. An unqualified request remains valid when its selected CFT row declares one skin. Without a row/identity or side selection, conflicting declarations do not become a default just because another skin file is missing. [Thirty-three guard mesh rows](evidence/characteritem-side-20261105-guards.tsv) cover these selectors, conflicting sides, absent selectors, invalid and divergent DTX copies, and an invalid model duplicate.

The follow-up [structure inventory](evidence/characteritem-side-20261105-structure-models.tsv) fully consumed 91 physical LTB files: [182 nodes](evidence/characteritem-side-20261105-structure-nodes.tsv), [91 embedded animations](evidence/characteritem-side-20261105-structure-animations.tsv), and [one socket](evidence/characteritem-side-20261105-structure-sockets.tsv). Every file has two nodes and one embedded animation. `IFF_Shoulder.LTB` contains `Effect` on node 1. That embedded socket does not prove which other asset attaches to it; raw CFT target enums remain unverified external bindings.

All 533 previously confirmed register records passed regression checks: the initial CharacterItem set's 502 records are covered by [516 physical slot rows with identical PNG bytes](evidence/characteritem-side-20261105-base-regression.tsv), and [31 other records](evidence/characteritem-side-20261105-other-regression.tsv) retain their declared paths against the recorded focused resources. One prior unverified MasterHERO hair fallback is now unresolved without a side; its two side-specific records are confirmed. The full CFT audit retains 13,598 typed model rows, with [eight texture-field corrections](evidence/characteritem-side-20261105-cft-deltas.tsv) and [two removed directory-only pairings](evidence/characteritem-side-20261105-cft-removed-rows.tsv). ### CharacterItem base fields

The initial 2026-11-05 batch covers 260 typed model rows from 174 CharacterItem records and 228 distinct model paths. It scanned all 482 REZ archives without errors, extracted 759 physical resources, and verified their stored bytes after rebuilding 12 filtered archives. The [resource manifest](evidence/characteritem-base-20261105-resources.tsv) and [736 requested paths](evidence/characteritem-base-20261105-targets.tsv) retain archive identities, hashes and missing paths.

Base fields can reference exact DTX paths anywhere under `ModelTextures/`, including `Character` and `Wave`. Binding still requires one unambiguous base path, slot 0 in every decoded model copy, matching slot layouts, and decodable texture copies with identical bytes or equivalent decoded pixels. Multiple-slot models also require a numbered texture field.

Seven [export jobs](evidence/characteritem-base-20261105-jobs.tsv) produced 523 physical mesh-slot rows: 516 confirmed, five written but unverified, and two unresolved. Nineteen formerly unresolved rows now export; all 502 baseline written rows retain identical PNG SHA-256. One existing mesh-derived binding now uses its explicit CFT field. Every one of the 521 written rows matches the decoded pixel hash of a recorded source DTX. The [slot evidence](evidence/characteritem-base-20261105-export-slots.tsv) records the exact CFT row, physical model source, selected texture copies, pixel hash and validation status.

The [486 physical DTX records](evidence/characteritem-base-20261105-texture-copies.tsv) expose three paths with different decoded pixels across archive versions: CFPL GR headset, The_Fates_Casual GR hair and GR hat. The hair base remains unresolved. Four numbered headset/hat exports were marked unverified in that snapshot; v1.2.9 no longer writes those PNGs. The initial MasterHERO hair fallback was unverified because its row declares different GR and BL base textures; the side follow-up now rejects that unqualified fallback and confirms both hair and pouch skins with explicit side contexts.

Five requested DTX paths were absent from all REZ archives. They belong to numbered fields for which these decoded models have no slot. They remain declarations, rather than export failures or inferred bindings. The [260 CFT mappings](evidence/characteritem-base-20261105-cft-links.tsv) retain every original field.

The [structure inventory](evidence/characteritem-base-20261105-structure-models.tsv) completely parsed 272 physical LTB files, including related models: [544 nodes](evidence/characteritem-base-20261105-structure-nodes.tsv), [272 embedded animations](evidence/characteritem-base-20261105-structure-animations.tsv), and [zero embedded sockets](evidence/characteritem-base-20261105-structure-sockets.tsv). Each has two nodes and one embedded animation. Raw CFT attachment fields are retained [separately](evidence/characteritem-base-20261105-attachment-fields.tsv); their target-type enums do not establish an external bone binding. [Guard results](evidence/characteritem-base-20261105-guards.tsv) include an invalid duplicate Character DTX that blocks base slot 0 while retaining numbered slot 1.
