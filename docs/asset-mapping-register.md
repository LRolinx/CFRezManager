# Asset Mapping Register

`asset-mapping-register.tsv` is a versioned reference record of confirmed model-to-texture slots and table-declared relationships. Published packages include it under `docs/`. The runtime resolver does not load this register; unverified rows do not change export behavior.

## Status

- `exported-slot`: the focused OBJ export's texture-slot report marked this model, mesh, and slot as exported.
- `exported-slot-unverified`: the export wrote a texture, but conflicting physical copies or multiple side-specific fields leave the intended binding unconfirmed. The written texture must not be treated as a confirmed game mapping.
- `table-declared-slot-unverified`: a typed CFT row declares the model and texture fields, but the model slot has not been verified by export.
- `model-resource-missing`: the table declares the model, but the current resource scan did not find its file. Any listed texture and motion paths remain table declarations.
- `model-reference-incomplete`: the source field names a directory without a complete model filename. The record retains the original field and any same-side texture declaration; no model slot is established.
- `slot-unresolved`: the model and slot were decoded, but the focused export did not establish a texture binding, including cases where the logical path is known but its physical copies conflict.

Rows describe individual slots. A successful row can coexist with other unresolved meshes in the same OBJ export.

## Fields

- `model_path` and `texture_path` use paths relative to the game resource root.
- `global_texture_slot` is the LTB skin slot; it is blank until slot evidence exists.
- `mapping_source_or_field` names the resolver source for exported slots or the CFT field for declared relationships.
- `skeleton_or_bone_names` records a node count and hierarchy hash when inspected; the linked node table retains every name and parent. Counts include the scene root.
- `bone_or_socket_binding` records embedded model sockets, inspected native vertex-skin methods, sampled pose status or the raw CFT attachment target type. The linked tables retain physical sources, bone indices and weighted vertex/corner counts. An embedded socket does not establish which accessory uses it. Blank values mean unknown, not absent.
- `motion_model_path` records a motion reference from the typed CFT row or a serialized LTB child-model declaration. A logical path does not select a physical version. It does not claim that OBJ export contains the animation.
- OBJ currently exports geometry and textures. It does not preserve skeleton bones or animation tracks.

Starting with v1.2.7, opening a CFT displays all decoded rows in a table with row numbers, original field names, a frozen `RecordId` column and numeric sorting. Export XLSX from the preview window, the file context menu or with `--export-cft-xlsx --input <file.cft> --output <file.xlsx>`. Its first column is the serialized `RecordId`; it is distinct from the zero-based row selector used in this register. Export preserves source order regardless of preview sorting. The [preview checks](evidence/cft-grid-20261105-validation.tsv) cover both CharacterType and CharacterItem, including every cell and duplicate-column guards.

## Snapshot

The register contains 10,465 records: 8,145 confirmed exports, 678 unresolved slots, seven written but unverified slots, eight declarations without a matching decoded slot, 1,624 missing-model declarations and three incomplete model references. Records include explicit row and side contexts, so several records can describe different selected skins on the same model slot. These are recorded samples, not a full-game coverage count. Physical model copies remain separate in the evidence tables and are deduplicated by context, logical model, mesh name and slot in the register.

### Native vertex-skin records

The same 37 physical PView, QV and arm files contain [160 LOD0 meshes](evidence/native-skin-20261105-meshes.tsv): 88 use direct draw bindings and 72 use a rigid effector. An [independent reader](evidence/native-skin-20261105-validation.tsv) reproduced all 141,464 vertex bindings and float32 weights, 150,648 triangles, [2,395 draw groups](evidence/native-skin-20261105-draws.tsv) and all 2,146 existing hierarchy/bind-matrix records. The [1,926 bone-usage rows](evidence/native-skin-20261105-bone-usage.tsv) retain each mesh's weighted node indices, names, parent indices, vertex/corner counts and weight ranges. That inspection added binding evidence to 869 existing rows without changing their texture paths or export statuses.

Direct bindings follow the triangles actually drawn by each bone set. A set's index-buffer value is its cumulative end; its vertex range alone does not assign ownership. The optional capture API retains per-corner overrides when shared vertices use different palettes. Stored weights keep their decoded float32 values, and the final active influence is `1 - sum(previous weights)` without clamping or normalization. This snapshot has no corner overrides, undrawn vertices without a binding, or weights outside the unit interval.

Matrix-palette handling has [synthetic checks](evidence/native-skin-20261105-guards.tsv), but no real sample in this snapshot. Its minimum is a range bound rather than an offset added to the raw byte index. Remapped global node indices may exceed 255; palette byte 255 is distinct from the direct bone-set terminator. The 63 checks also cover overlapping draws, malformed weights/ranges, multiple streams, serialized skeleton indices and geometry preservation.

The [skin check tool](../tools/NativeSkinCheck/README.md) captures data through the node hierarchy; complete-file validation remains the separate structure audit. Ordinary preview and OBJ decoding retain their existing geometry path without allocating skin arrays. Per-mesh skin errors remain explicit while static geometry stays available. Physical motion-version selection, rendered animation and animated export remain unverified; OBJ still exports geometry and textures.

### Native pose samples

The [pose source inventory](evidence/native-pose-20261105-sources.tsv) checks the same 37 physical files against their complete structure/channel report and stored/decoded SHA-256. Twenty-one files contain 85 embedded animations. Sampling each animation's first/last key and the midpoint of its longest positive key interval produces [241 poses](evidence/native-pose-20261105-poses.tsv). Single-key animations contribute one pose. Sixteen variants have no embedded animation; their declared external children remain unselected.

The [independent comparison](evidence/native-pose-20261105-validation.tsv) covers 19,340 node pose records, each containing local/global/skin matrices, and [1,273 posed mesh records](evidence/native-pose-20261105-meshes.tsv), totaling 1,100,023 vertex positions. A separate column-vector calculation differs by at most 0.000017543 matrix units and 0.000008037 vertex units. Recorded tolerances are absolute 0.0005 plus relative 0.000005. Mesh rows retain the exact float32 position hash and bounds. Raw pose matrices and binary vertices can be regenerated locally; game resources are not committed.

Evaluation uses parent-to-child animation transforms, the native rigid bind inverse and each self binding's root translation. Forty-five sampled poses have a nonzero root translation. Rotation-only nodes use their parent-relative bind offset; this snapshot has no such flags, so that behavior has synthetic coverage. Quaternion interpolation follows the shortest arc, and conversion to a matrix accounts for quaternion magnitude without changing the recorded channels. Finite skin weights are used without normalization, including per-corner overrides when needed.

The [90 checks](evidence/native-pose-20261105-guards.tsv) include the original 63 skin checks and 27 pose/CPU-skin checks. [Nine input checks](evidence/native-pose-20261105-input-guards.tsv) cover source/report mismatches, partial or vertex channels, self binding names and clearing stale pose outputs. The [inspection marker](evidence/native-pose-20261105-inspection.tsv) records requested detail. This updates 869 register rows: 866 link to sampled embedded poses and three retain an unselected external child. Texture paths and statuses remain unchanged. Sampling is not continuous playback validation; animation blending, node controllers, external-child retargeting, export coordinate conversion and the game's rendered result remain unverified.

### Texture copy consistency

v1.2.9 compares every decoded copy of a logical texture path. Matching index MD5 values or a valid MD5 on each individual file do not establish pixel equivalence. Every copy must decode with matching dimensions and BGRA pixels, including alpha. The [six recorded physical DTX copies](evidence/texture-copy-20261105-variants.tsv) cover three conflicting paths: CFPL GR headset and The_Fates_Casual GR hair/hat. All six actual MD5 values match their index entries, but each logical path has two different pixel hashes. A [fresh scan of all 482 archives](evidence/texture-copy-20261105-scan.tsv) reproduced their stored hashes. The active game copy remains unverified; directory numbering is not used to choose one.

The [four prior unverified outputs](evidence/texture-copy-20261105-conflict-status.tsv) now retain their original CFT references without writing a PNG. Their per-slot export report says `export-failed`, which means the PNG was not written; both source copies can individually decode. The register marks these slots unresolved until a physical version can be established. The hair base was already unresolved for the same conflict. All [915 confirmed records](evidence/texture-copy-20261105-confirmed-regression.tsv), covering 939 physical mesh-slot witnesses, retain identical PNG bytes to v1.2.8.

The GUI and command-line OBJ exporters use the same lookup policy: a matching resource that is undecodable or conflicting does not fall through to another extension or a nearby local copy. A path absent from the global index can still use local lookup. Explicit physical paths remain individually readable. Standard bitmap decoding also precedes raw-TGA recovery, preventing valid PNG metadata from changing the interpreted image dimensions.

The [61 checks](evidence/texture-copy-20261105-guards.tsv) include changed first/last-row RGB and alpha, dimensions, invalid copies, reversed order, MD5 metadata, explicit physical references, recognized but invalid PNG data and PNG metadata whose encoded size resembles raw TGA. The [reusable check tool](https://github.com/LRolinx/CFRezManager/tree/main/tools/TextureCopyCheck) runs 49 synthetic cases without game files; these cases also run in the release workflow. Twelve additional checks use the recorded DTX snapshot.
