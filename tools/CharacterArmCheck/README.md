# Character context checks

Run from the repository on Windows with the .NET 8 SDK:

```powershell
dotnet run --project tools/CharacterArmCheck -c Release
```

The arm fixture uses a native two-piece triangle LTB, a two-row CharacterType CFT and eight small PNG textures under a unique `artifacts/character-arm-check/` directory. No game files are required. Both sides deliberately share a model whose filename ends in `_GR`; the declared model columns must retain both GR and BL skins.

The 67 arm checks cover side-qualified row, identity and positive RecordId selectors, reused models with different row skins, ambiguous unqualified contexts, absent selectors and the distinction between row indices and record identifiers, reversed hand/arm slots, deferred fallback indexing, early success without further name guesses and retained SGFX auxiliary output. Four ordinary command-line OBJ exports must use the declared fields and preserve every texture pixel. Results default to `artifacts/character-arm-check/results.tsv`; `--output <report.tsv>` selects another path.

The body group contains 101 checks. Their separate CFT keeps ordinary, ModelFile2 and BattleRoyal GR/BL columns, unnumbered base textures and TextureFile2. Model and texture filenames deliberately use the opposite side suffix. Row, identity and RecordId selectors must still choose the declared side. Eight body OBJ exports preserve both slots and pixels; a ninth keeps geometry and the second texture when the base texture is missing. An invalid physical model copy blocks base-slot binding, and a missing side does not become the other side's default.

The [body snapshot](../../docs/evidence/character-bodies-20261105-export-slots.tsv) covers 3,888 row/model/side cases and 4,925 physical stage-slot witnesses. It records 283 new outputs, 11 corrected skins, 4,002 byte-identical PNGs, one stopped fallback and five unverified outputs. The [source inventory](../../docs/evidence/character-bodies-20261105-resources.tsv) and [raw fields](../../docs/evidence/character-bodies-20261105-raw-fields.tsv) retain paths, copies and declarations independently of the export result.

The socket-item group contains 69 checks after the 168 arm/body cases. A CharacterItem CFT uses separate and shared side models, opposite filename suffixes and DTX values deliberately placed in model columns. Only the declared GRTexFile/BLTexFile fields can supply the primary model slots. Six CLI exports check original DTX pixels, all selector forms and an absent base field while retaining the valid second texture. Unique-side models also accept the unqualified row selector. The body missing-texture fixture uses a never-created unique filename so older local exports cannot satisfy the lookup.

The [complete CharacterItem scope](../../docs/evidence/characteritem-all-20261105-export-slots.tsv) checks 5,927 model-reference/side cases and 6,544 physical stage slots. Thirty-eight outputs are new, and 6,452 retain identical PNG bytes against the prior source version. A [legacy-selector comparison](../../docs/evidence/characteritem-all-20261105-legacy-validation.tsv) separately corrects eight written bindings and eight unused declarations in the existing register. Raw malformed fields remain recorded without being promoted into model bindings.

The Nano group adds 120 checks after the preceding 237 arm/body/socket cases. Its three-piece body retains base and zero-based numbered skins. Separate slot-0 accessories pair with SocketSkinFileName1/2 by accessory number; these fields do not spill into the body or each other. Twelve CLI exports check row, identity and positive RecordId selectors, native DTX pixels, a never-created base reference and conflicting base declarations while keeping valid later slots. A schema without NanoType keeps its existing field interpretation. The [ten-table snapshot](../../docs/evidence/nano-family-20261105-export-slots.tsv) checks all 1,033 model cases and 3,883 physical stage-slot witnesses, with 1,221 new confirmed outputs and 2,530 unchanged PNGs. Its one spelling fallback remains unverified.

The AI group adds 76 checks after the preceding 357 arm/body/socket/Nano cases. Typed texture fields preserve DTX paths under Models/ as well as ModelTextures/. Explicit child columns identify related assets without a filename keyword; six CLI exports verify inherited slots, exact pixels and row/identity/positive RecordId selectors. A child-only numbered slot is checked against its native layout. A missing parent or an invalid child copy blocks inheritance, while a same-file child declaration preserves primary texture ownership. The [AI snapshot](../../docs/evidence/ai-family-20261105-export-slots.tsv) covers 1,856 model cases and 5,043 physical stage slots, with 16 new confirmed outputs and 4,268 unchanged PNGs. Mesh-rule outputs without a matching row field remain unverified.

The CharacterPvItem group adds 86 checks, bringing the suite to 519. Extensionless socket-model prefixes expand only under Models/PVItem/ in the named table. Every physical candidate must decode with a consistent native slot set. Seven CLI exports preserve row/name/positive RecordId selectors, original DTX pixels and valid later slots when the base is missing. Complete filenames, other tables and other directories do not gain gender aliases. Invalid male copies or differing physical slot sets block male inheritance; the valid female binding remains intact. The [932-case snapshot](../../docs/evidence/view-items-20261105-export-slots.tsv) records 210 new outputs, two corrected female ring skins and 822 unchanged PNGs; all exported geometry remains identical.

The release workflow runs these checks before packaging. [Texture-copy checks](../TextureCopyCheck/README.md) separately verify conflicting physical resources; [structure checks](../LtbStructureAudit/README.md) cover nodes, child declarations, bindings and animation blend masks. These checks do not validate animation playback or vertex skinning.

The structure check also covers animation channel encodings, hierarchy traversal and raw keyframe events. The [PView node map](../../docs/evidence/pview-motion-20261105-arm-node-map.tsv) records the 46 shared arm nodes separately from bind-matrix and playback validation.

The separate [native skin checks](../NativeSkinCheck/README.md) verify direct draw bindings, rigid effectors and matrix-palette edge cases. The 37-file PView/arm snapshot retains verified skin hashes for 160 meshes and 141,464 vertices. These are decoded binding records; rendered arm animation remains unverified.

The skin tool now also evaluates sampled native poses from a completed channel report. Its [241-pose comparison](../../docs/evidence/native-pose-20261105-validation.tsv) includes the basic arm templates and preserves each physical source. CPU pose calculations do not establish an active character/weapon animation binding or change the side-qualified texture selection.
